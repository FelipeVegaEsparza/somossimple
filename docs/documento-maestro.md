La idea es que este documento sea la fuente de verdad del producto: qué es, para quién es, qué módulos tiene, qué puede hacer cada uno, reglas de negocio, flujo de usuarios y qué queda fuera del MVP.

Documento Maestro — Plataforma Digital para Negocios

# 1. Visión del producto

La plataforma permite que cualquier negocio, profesional o persona que ofrezca productos o servicios pueda tener una presencia digital propia, accesible desde un enlace, código QR o dispositivo NFC.

El objetivo es reunir en un solo lugar:

- Información del negocio.
- Servicios, productos o menú.
- Reservas.
- Clientes.
- Comunicaciones.
- Accesos mediante QR y NFC.
- Estadísticas básicas.

La plataforma debe ser suficientemente sencilla para que una persona sin conocimientos técnicos pueda crear y administrar su presencia digital.

## Concepto central

La plataforma digital de tu negocio.

El QR y NFC no son el producto principal. Son los puntos físicos de acceso al producto digital.

El cliente puede encontrarse con un soporte físico sobre una mesa, mostrador, vehículo, recepción, local comercial u otro lugar y acceder inmediatamente al perfil digital del negocio.

# 2. Problema que resuelve

Actualmente muchos pequeños negocios y profesionales utilizan múltiples herramientas independientes:

- Instagram para mostrar su negocio.
- WhatsApp para contactar clientes.
- Google Maps para ubicación.
- Un sitio web para información.
- Calendarios para reservas.
- Formularios para captar clientes.
- Excel o libretas para registrar clientes.
- Herramientas de email para enviar promociones.

Esto genera complejidad y hace difícil administrar la presencia digital.

La plataforma busca centralizar las funciones esenciales en un único lugar.

# 3. Público objetivo

La plataforma está orientada principalmente a pequeños negocios, emprendedores y profesionales.

## Ejemplos

- Pastelerías.

**Belleza y cuidado personal**

- Barberías.
- Peluquerías.
- Salones de belleza.
- Manicure.
- Masajes.

**Servicios profesionales**

- Fotógrafos.
- Diseñadores.
- Técnicos.
- Gasfíteres.
- Electricistas.
- Plomeros.
- Mecánicos.

**Comercio**

- Almacenes.
- Tiendas.
- Emprendimientos.

- Tiendas especializadas.

**Servicios**

- Centros médicos.
- Centros de estética.
- Profesionales independientes.

- Otros negocios que necesiten contacto, servicios o reservas.

La plataforma no debe estar limitada a un rubro específico.

# 4. Modelo conceptual

El producto está compuesto por tres elementos principales:

## 4.1. Plataforma

Es el software donde el negocio administra su información.

## 4.2. Perfil digital

Es la página pública del negocio.

Ejemplo:

`plataforma.cl/p/barberia-patagonia`

El enlace debe ser estable.

## 4.3. Acceso físico

El perfil puede estar conectado a:

- QR digital.
- QR físico.
- NFC.
- Soportes 3D.
- Tarjetas.
- Adhesivos.
- Otros elementos físicos.

El objeto físico simplemente dirige al perfil digital.

# 5. Estructura comercial

La plataforma utiliza un modelo freemium.

## Módulo gratuito: Perfil Digital

Es el punto de entrada al producto.

Debe ser suficientemente completo para que un negocio pueda utilizarlo sin pagar.

Incluye:

- Nombre del negocio.
- Logo.
- Imagen de portada.
- Descripción.
- Fotografías.
- Dirección.
- Ubicación en Google Maps.
- Horarios.
- Teléfono.
- WhatsApp.
- Correo electrónico.
- Redes sociales.
- Sitio web.
- Botones personalizados.
- URL pública.
- Código QR digital.

No se debe exigir tarjeta de crédito para utilizar el perfil gratuito.

# 6. Módulos de pago

La plataforma tendrá cinco módulos principales.

| Módulo | Estado |
| --- | --- |
| Perfil Digital | Gratis |
| Catálogo | Pago |
| Reservas | Pago |
| Clientes / CRM | Pago |
| Comunicaciones | Pago |

El cliente podrá activar solamente los módulos que necesite.

No todos los negocios necesitan todas las funcionalidades.

# 7. Módulo 1 — Perfil Digital

El perfil es la página pública principal del negocio.

## Información

Debe permitir administrar:

- Nombre comercial.
- Descripción.
- Logo.
- Imagen de portada.
- Galería de imágenes.
- Dirección.
- Ubicación.
- Horarios.
- Teléfono.
- WhatsApp.
- Email.
- Sitio web.
- Redes sociales.

## Redes sociales

Debe permitir agregar enlaces a redes sociales utilizadas por el negocio.

Por ejemplo:

- Instagram.
- Facebook.
- TikTok.
- YouTube.
- LinkedIn.

No se debe limitar innecesariamente la cantidad de redes soportadas.

## Botones personalizados

El negocio puede crear botones adicionales.

Ejemplos:

- "Ver nuestro Facebook".
- "Visitar tienda online".
- "Solicitar presupuesto".
- "Hablar con nosotros".
- "Ver ubicación".

# 8. Perfil dinámico

El perfil debe mostrar solamente las funcionalidades que el negocio tenga activadas.

Por ejemplo:

**Negocio gratuito**

Muestra:

- Información.
- Contacto.
- Redes sociales.
- Ubicación.
- QR.

**Negocio con Catálogo**

Además muestra:

- Productos / servicios / menú.

**Negocio con Reservas**

Además muestra:

- Botón "Agendar hora".

**Negocio con ambos**

Muestra:

- Catálogo.
- Reservas.

La página pública nunca debe mostrar funcionalidades que el negocio no tenga disponibles.

# 9. Módulo 2 — Catálogo

No se deben crear sistemas separados para:

- Servicios.
- Productos.
- Menús.

Todos deben utilizar el mismo concepto: **Catálogo**.

El negocio puede decidir cómo presentar su catálogo.

## Elemento del catálogo

Cada elemento puede tener:

- Nombre.
- Descripción.
- Imagen.
- Precio.
- Categoría.
- Estado activo/inactivo.

Ejemplo para una barbería:

- Corte clásico — $12.000

Ejemplo para un restaurante:

- Hamburguesa Patagonia — $9.990

Ejemplo para un gasfíter:

- Instalación de calefont — Desde $50.000

El sistema no debe obligar a utilizar precios cuando el servicio no tenga un precio fijo.

# 10. Categorías

El catálogo puede organizarse por categorías.

Ejemplos:

**Restaurante**

- Entradas.
- Platos principales.
- Postres.
- Bebidas.

**Barbería**

- Cortes.
- Barba.
- Tratamientos.

**Tienda**

- Electrónica.
- Hogar.
- Accesorios.

Las categorías son opcionales.

# 11. Módulo 3 — Reservas

El módulo de reservas permite que un cliente pueda solicitar una hora directamente desde el perfil.

Debe mantenerse simple.

No pretende reemplazar inicialmente sistemas complejos de gestión de calendarios.

## Configuración

El negocio puede configurar:

- Servicios disponibles.
- Duración de cada servicio.
- Precio.
- Horarios de atención.
- Días de atención.
- Días no disponibles.

## Flujo del cliente

1. Ingresa al perfil.
2. Selecciona "Agendar".
3. Selecciona un servicio.
4. Selecciona una fecha.
5. Selecciona una hora disponible.
6. Ingresa su nombre.
7. Ingresa teléfono.
8. Opcionalmente ingresa email.
9. Confirma la solicitud.

# 12. Estados de una reserva

Las reservas tendrán estados simples:

- Pendiente.
- Confirmada.
- Cancelada.
- Completada.

El negocio puede administrar estos estados desde su panel.

# 13. Agenda

El negocio debe poder consultar sus reservas.

La visualización inicial debe ser sencilla.

Debe permitir consultar:

- Día.
- Semana.
- Horario.
- Cliente.
- Servicio.
- Estado.

No se deben incorporar inicialmente integraciones complejas con calendarios externos.

# 14. Módulo 4 — Clientes / CRM

El CRM permite que cada negocio tenga una base de clientes propia.

No pretende competir con plataformas empresariales como HubSpot.

Debe ser simple y práctico.

## Información del cliente

Puede almacenar:

- Nombre.
- Teléfono.
- Email.
- Fecha de registro.
- Etiquetas.
- Notas.
- Historial de reservas.
- Consentimiento para comunicaciones comerciales.

# 15. Creación de clientes

Un cliente puede ingresar al CRM mediante diferentes acciones.

**Reserva**

Cuando una persona realiza una reserva, puede crearse automáticamente como cliente.

**Registro voluntario**

El negocio puede mostrar: "¿Quieres recibir nuestras promociones?"

El visitante puede ingresar:

- Nombre.
- WhatsApp o teléfono.
- Email.

Debe existir una aceptación explícita para recibir comunicaciones comerciales.

**Registro manual**

El propietario puede crear clientes directamente desde el panel.

# 16. Segmentación de clientes

El negocio podrá organizar sus clientes mediante categorías o etiquetas.

Ejemplos:

- Nuevo.
- Frecuente.
- VIP.
- Inactivo.
- Cliente habitual.
- Cumpleaños.
- Interesado.

También podrá crear etiquetas personalizadas.

No es necesario crear un sistema avanzado de segmentación para el MVP.

# 17. Historial

El perfil de un cliente puede mostrar información relacionada con su relación con el negocio.

Por ejemplo:

- Cliente: Juan Pérez
- Primera reserva: 02/09/2026.
- Última reserva: 08/09/2026.
- Reservas realizadas: 5.
- Estado: Cliente frecuente.
- Etiquetas: VIP.

# 18. Módulo 5 — Comunicaciones

Este módulo convierte el CRM en una herramienta comercial.

Permite al negocio comunicarse con sus clientes.

Inicialmente el canal principal será: **Email**.

No se debe construir inicialmente una plataforma propia de WhatsApp masivo.

## Tipos de comunicación

El negocio puede crear:

- Promociones.
- Ofertas.
- Anuncios.
- Noticias.
- Cambios de horario.
- Comunicaciones generales.

# 19. Destinatarios

Las comunicaciones pueden enviarse a:

- Todos los clientes con consentimiento.
- Clientes nuevos.
- Clientes frecuentes.
- Clientes inactivos.
- Clientes VIP.
- Una etiqueta determinada.

Ejemplo: "Enviar promoción a clientes VIP."

# 20. Regla importante de comunicaciones

La autorización para recibir comunicaciones comerciales debe ser independiente de la creación del cliente.

Una persona puede ser cliente sin aceptar publicidad.

Por lo tanto: **Cliente ≠ necesariamente suscriptor de comunicaciones.**

Esto debe mantenerse claramente separado.

Las comunicaciones operacionales necesarias para una reserva pueden tratarse de forma diferente a las comunicaciones comerciales.

# 21. QR y NFC

QR y NFC son mecanismos de acceso al perfil digital.

El principio fundamental es:

**El QR/NFC nunca debe depender del contenido físico del negocio.**

Debe apuntar a una dirección estable.

Ejemplo: `plataforma.cl/p/barberia-patagonia`

Si el negocio modifica teléfono, Instagram, servicios, precios, fotografías u horarios, no necesita modificar ni reimprimir su QR.

# 22. Productos físicos

La plataforma puede comercializar diferentes productos físicos.

- QR: Tarjetas, adhesivos, carteles, displays.
- NFC: Tarjetas NFC, tags NFC, soportes.
- QR + NFC: Un mismo producto puede incorporar ambas tecnologías.

**Productos 3D**

El sistema puede complementar el negocio con productos personalizados fabricados mediante impresión 3D.

Ejemplos:

- Soporte de mesa.
- Display.
- Porta menú.
- Identificador.
- Señalética.

Estos productos tienen un costo único, independiente de la suscripción de software.

# 23. Múltiples accesos físicos

Un mismo negocio podrá eventualmente tener varios accesos.

Ejemplo de restaurante:

- Entrada.
- Recepción.
- Mesa 01.
- Mesa 02.
- Mesa 03.

Cada acceso puede estar asociado al mismo negocio.

En el futuro podrá identificarse cada uno individualmente para obtener estadísticas.

Para el MVP no es necesario crear una gestión compleja de dispositivos.

# 24. Estadísticas

El panel debe ofrecer estadísticas básicas.

Como mínimo:

- Visitas al perfil.
- Escaneos QR.
- Accesos NFC.
- Clicks en WhatsApp.
- Clicks en Instagram.
- Reservas.

Las estadísticas deben ser fáciles de comprender.

El objetivo no es crear una plataforma de analítica avanzada.

# 25. Dashboard

El propietario tendrá un panel central de administración.

## Secciones principales

- Dashboard: Resumen general.
- Perfil: Administración del perfil público.
- Catálogo: Productos, servicios o menú.
- Reservas: Agenda y configuración.
- Clientes: Base de clientes.
- Comunicaciones: Campañas y mensajes.
- QR / NFC: Información y gestión de accesos físicos.
- Configuración: Cuenta, negocio, suscripción y preferencias.

# 26. Dashboard principal

Debe mostrar información útil inmediatamente.

Ejemplo:

- Visitas del perfil: 1.245
- Escaneos QR: 328
- Accesos NFC: 174
- Clientes: 86
- Próximas reservas: 7

También puede mostrar:

- Actividad reciente.
- Próximas reservas.
- Nuevos clientes.
- Acciones rápidas.

# 27. Activación de módulos

El negocio debe poder activar módulos desde el panel.

Ejemplo:

- Mis módulos
- Perfil Digital — Activo — Gratis
- Catálogo — Activar
- Reservas — Activar
- Clientes — Activar
- Comunicaciones — Activar

La interfaz debe dejar claro qué está activo y qué no.

# 28. Reglas de activación

Cuando un módulo está desactivado:

- No aparece en el perfil público.
- No aparece como funcionalidad disponible para los visitantes.
- Sus datos no deben eliminarse.

Cuando se vuelve a activar:

- La información debe continuar disponible.

Esto evita pérdida de datos.

# 29. Suscripciones

El modelo comercial contempla que los módulos de pago funcionen mediante suscripción.

Sin embargo, los precios y planes comerciales serán definidos posteriormente.

La plataforma debe conceptualmente diferenciar:

- Funcionalidades gratuitas.
- Funcionalidades pagadas.
- Estado de activación de cada módulo.

# 30. Expiración de una suscripción

Si una suscripción de un módulo de pago termina:

- El módulo deja de estar disponible públicamente.
- Los datos del módulo no deben eliminarse inmediatamente.
- El negocio debe poder recuperar/reactivar el módulo posteriormente.
- El perfil gratuito continúa funcionando.

Ejemplo:

Una barbería deja de pagar Reservas.

Su perfil continúa mostrando logo, información, WhatsApp, Instagram y ubicación.

Pero:

- El botón "Agendar" deja de estar disponible.
- Los servicios y reservas almacenados no deben eliminarse automáticamente.

# 31. El perfil gratuito nunca depende del QR físico

Aunque un cliente deje de pagar módulos:

- Su perfil gratuito puede continuar existiendo.

Por lo tanto, un QR físico vendido anteriormente seguirá llevando al perfil.

Esto evita que el producto físico quede inutilizado.

# 32. Propiedad de los datos

Cada negocio debe tener acceso exclusivamente a sus propios datos.

Un negocio no puede:

- Ver clientes de otro negocio.
- Ver reservas de otro negocio.
- Ver comunicaciones de otro negocio.
- Modificar información de otro negocio.

El propietario controla la información de su negocio.

# 33. Cuenta de usuario

Para el MVP:

- Una cuenta → un negocio.

No se necesita inicialmente:

- múltiples empresas por usuario;
- empleados;
- roles;
- permisos;
- administradores secundarios.

La estructura conceptual debe permitir eventualmente evolucionar hacia eso, pero no debe formar parte del MVP.

# 34. Diseño para móviles

El perfil público debe estar pensado principalmente para teléfonos móviles.

La mayoría de los accesos mediante QR y NFC ocurrirán desde smartphones.

Por lo tanto:

- Botones grandes.
- Información clara.
- Carga rápida.
- Navegación sencilla.
- WhatsApp visible.
- Teléfono accesible.
- Ubicación fácil de encontrar.
- Reservas fáciles de completar.

# 35. Experiencia del visitante

El visitante no debe sentir que está utilizando una aplicación compleja.

Debe funcionar como una página digital extremadamente sencilla.

Ejemplo:

```
BARBERÍA PATAGONIA

[Foto]

"Barbería masculina en Chile Chico."

📍 Ubicación
📞 Llamar
💬 WhatsApp
📷 Instagram

Servicios

Corte clásico — $12.000
Corte + barba — $18.000

Reservas

Agendar hora

Redes

Instagram | Facebook
```

# 36. Experiencia del propietario

El propietario debe poder entender la plataforma sin capacitación técnica.

Al ingresar debe comprender inmediatamente: "Aquí está mi negocio y desde aquí administro todo."

Las funciones deben ser claras y evitar terminología técnica innecesaria.

# 37. Flujo general del producto

El recorrido ideal del cliente será:

```
CREA SU CUENTA
      ↓
CREA SU PERFIL
      ↓
PUBLICA SU PERFIL GRATUITO
      ↓
COMPARTE SU URL / QR
      ↓
ADQUIERE QR / NFC FÍSICO
      ↓
LOS CLIENTES ACCEDEN
      ↓
ACTIVA CATÁLOGO
      ↓
ACTIVA RESERVAS
      ↓
CAPTA CLIENTES
      ↓
ACTIVA COMUNICACIONES
      ↓
FIDELIZA Y GENERA NUEVAS VENTAS
```

Este flujo es fundamental para el modelo de negocio.

# 38. El ciclo de valor

La plataforma debe crear un ciclo continuo:

```
QR / NFC
   ↓
VISITANTE
   ↓
PERFIL DIGITAL
   ↓
CONTACTO / RESERVA
   ↓
CLIENTE
   ↓
CRM
   ↓
COMUNICACIÓN
   ↓
NUEVA VISITA / COMPRA
   ↓
CLIENTE RECURRENTE
```

Este ciclo es uno de los elementos más importantes del producto.

El objetivo no es solamente entregar una tarjeta digital.

El objetivo es ayudar al negocio a convertir visitantes en clientes y clientes en clientes recurrentes.

Para mantener el producto simple, las siguientes funcionalidades quedan fuera inicialmente:

- Facturación electrónica.
- Punto de venta.
- Contabilidad.
- Inventario avanzado.
- ERP.
- Marketplace.
- Delivery.
- Sistema clínico.
- Fichas médicas.
- Ecommerce completo.
- Gestión avanzada de empleados.
- Roles complejos.
- Calendario avanzado.

- Sistema de puntos.

Estas funcionalidades pueden evaluarse posteriormente, pero no deben ser inventadas durante el desarrollo del MVP.

# 44. Principios del producto

El desarrollo debe respetar estos principios:

1. **Simplicidad**: si una funcionalidad puede resolverse de forma sencilla, debe preferirse esa opción.
2. **Modularidad**: cada negocio activa solamente lo que necesita.
3. **Perfil primero**: el perfil digital es el corazón del producto.
4. **Mobile first**: el visitante normalmente llegará desde un teléfono.
5. **Sin pérdida de datos**: desactivar un módulo no significa eliminar sus datos.
6. **Sin dependencia del hardware**: QR y NFC deben apuntar a una dirección estable.
7. **No sobrecargar al usuario**: el propietario debe poder administrar su negocio sin conocimientos técnicos.
8. **Una plataforma, muchos tipos de negocio**: no crear sistemas separados para cada industria cuando una funcionalidad genérica pueda resolver el problema.

# 46. Lo que NO debe hacer el desarrollador por su cuenta

Este punto es especialmente importante para el desarrollo asistido por IA.

El desarrollador o agente de IA no debe inventar funcionalidades que no estén definidas en este documento.

Si una funcionalidad no está especificada:

- No debe asumir que debe existir.
- No debe agregarla automáticamente.
- Debe considerarse fuera del alcance hasta que sea definida.

Si es indispensable para implementar una funcionalidad, debe identificarse explícitamente como una decisión pendiente.

El objetivo es evitar que el proyecto termine convirtiéndose en una plataforma excesivamente compleja.

# 47. Definición final del producto

La plataforma puede definirse de la siguiente manera:

Una plataforma digital para negocios y profesionales que permite crear un perfil digital propio y conectarlo con el mundo físico mediante QR y NFC, incorporando progresivamente catálogo, reservas, clientes y comunicaciones en un único lugar.

- El QR/NFC permite acceder.
- El perfil presenta el negocio.
- El catálogo muestra lo que vende.
- Las reservas permiten contratar.
- El CRM permite conocer a sus clientes.
- Las comunicaciones permiten volver a contactar con ellos.

# 48. Visión a futuro

El MVP debe resolver correctamente el núcleo del producto.

Posteriormente se podrá evolucionar hacia:

- WhatsApp Business API.
- SMS.
- Notificaciones push.
- Múltiples empleados.
- Múltiples sucursales.
- Integraciones de calendario.
- Automatizaciones.
- Cupones.
- Fidelización.
- Estadísticas avanzadas.
- Ecommerce.
- Más productos físicos.
- Gestión avanzada de QR/NFC.
- Integraciones externas.

Pero estas funcionalidades no forman parte del MVP actual.

# 49. Regla principal del proyecto

La plataforma debe poder resumirse en una sola frase:

"Le damos a cualquier negocio su propio lugar digital y las herramientas necesarias para convertir visitantes en clientes y clientes en clientes recurrentes."

Y el papel del QR/NFC es simple:

"Un toque o escaneo para entrar al negocio digital."
